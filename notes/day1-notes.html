What was actually built on Day 1

A landing page and a book-reading page for an AI learning app. No framework, no build step — plain HTML, CSS and JS. That constraint is why this project maps so well onto interview questions: everything a library would normally hide had to be written by hand.

Design tokens (CSS variables) Dark mode + theme switching localStorage persistence Event delegation IntersectionObserver Module pattern / IIFE Flexbox + Grid layouts Sticky header ARIA + keyboard access SVG icon system FOUC prevention Responsive breakpoints CSS animations Print stylesheet prefers-reduced-motion
Interview reality check Interviewers rarely ask "what is flexbox". They ask "you built X — why did you do it that way?" Every concept below is written with that follow-up in mind.

Part A — HTML Concepts

A1. Semantic HTML

Using the tag that describes the meaning of the content, not just a div. In the project: <header> for the site header, <main> for the chapter, <article> for the book page, <aside> for the margin note, <nav> for the chapter rail.

Why it matters: screen readers build a landmark map from these, search engines weight them, and other developers read your HTML like a document instead of a puzzle.

<header>   site or section header
<nav>      a block of navigation links
<main>     the ONE main content area (only one per page)
<article>  self-contained, makes sense on its own
<section>  a thematic group, usually needs a heading
<aside>    tangential content (margin notes, sidebars)
<footer>   footer of page or section
div is not banned — use it when there is genuinely no meaning, only layout.

A2. The viewport meta tag

<meta name="viewport" content="width=device-width, initial-scale=1">

Without it, mobile browsers render at ~980px wide and shrink the result, so your media queries never fire. width=device-width says "use the real device width". initial-scale=1 sets the starting zoom.

A3. data-* attributes and dataset

A standards-safe place to attach your own data to an element.

<button data-chapter="3" data-ico="check"></button>

el.dataset.chapter      // "3"  — always a string
el.dataset.ico          // "check"
Number(el.dataset.chapter)  // 3

Kebab-case in HTML becomes camelCase in JS: data-user-id → dataset.userId.

Used in the project data-theme, data-header and data-desk sit on <html>. CSS then styles off them — changing one attribute reskins the entire site with zero JavaScript styling.

A4. ARIA — the six you actually need

AttributeUse it for
aria-labelName an element with no visible text (icon buttons)
aria-expandedAccordions, dropdowns — true / false
aria-pressedToggle buttons that stay on
aria-currentCurrent page / step in a set ("page", "step")
aria-hiddenHide decoration from screen readers
aria-liveAnnounce dynamic updates (toasts)
Rule zero of ARIA No ARIA is better than bad ARIA. A native <button> beats <div role="button" tabindex="0"> every time — you get focus, Enter, Space and disabled behaviour free.

A5. Focus management & skip links

Keyboard users tab through in DOM order. A skip link is the first focusable element, hidden until focused, letting someone jump past the nav.

.skip-link{ position:absolute; transform:translateY(-200%); }
.skip-link:focus-visible{ transform:none; }   /* appears on Tab */

A6. Buttons, labels and forms

Always set type on a button. Inside a <form> the default is submit, which will reload your page unexpectedly.

<button type="button">  // does nothing by itself — for JS
<button type="submit">  // submits the form (default!)

<label>                 // wrapping = no id needed
  <input type="search">
</label>

A7. hidden vs display:none vs visibility

MethodIn layout?Screen reader?
hidden attributeNoNo
display:noneNoNo
visibility:hiddenYes (space kept)No
opacity:0YesYes — still read & clickable
.sr-onlyNo (1px clip)Yes — intentionally
Gotcha: hidden is beaten by any display rule. Add [hidden]{display:none!important}.

A8. Inline SVG and currentColor

<svg viewBox="0 0 24 24" fill="none" stroke="currentColor">
  <path d="M4 12h15"/>
</svg>

currentColor = "whatever color is on my parent". So one icon file works on light, dark and hover states with no extra CSS. viewBox defines the internal coordinate system, letting the icon scale to any size.

A9. Script loading & FOUC

DownloadsExecutes
plain <script>blocks parsingimmediately
asyncparallelas soon as ready — order not guaranteed
deferparallelafter HTML parsed, in order

FOUC / theme flash — if you apply a saved dark theme after the page paints, the user sees a white flash. Fix: one small blocking inline script in <head>, before the CSS renders.

<script>
  var s = JSON.parse(localStorage.getItem('settings') || '{}');
  document.documentElement.dataset.theme = s.theme || 'light';
</script>

A10. Useful "forgotten" elements

<kbd> keyboard key · <output> result of a calculation · <pre> preserves whitespace · <code> inline code · <blockquote> quotation · <time datetime=""> machine-readable date · <details>/<summary> native accordion, no JS.

Part B — CSS Concepts

B1. Custom properties (CSS variables)

:root{ --accent:#2A4C7D; }          /* global */
.btn{ background:var(--accent); }
.btn{ background:var(--brand, #333); } /* fallback */

They inherit and cascade — unlike Sass variables which are compiled away. That means you can override one on a child and everything inside it changes. This is what makes theming possible without JS.

B2. Theming with attribute selectors

:root            { --ink:#191814; --bg:#fff;   }
[data-theme=dark]{ --ink:#EDEAE3; --bg:#0E0E0D; }

body{ background:var(--bg); color:var(--ink); }

Flip document.documentElement.dataset.theme and the entire page re-themes. The JS never touches a single style — it only sets one attribute.

B3. Cascade, specificity, inheritance

When two rules collide, the winner is decided in this order:

  1. !important (avoid)
  2. Specificity — inline 1000, id 100, class/attribute/pseudo-class 10, element/pseudo-element 1
  3. Source order — last one wins
#nav .item      → 0,1,1,0  = 110  wins
.nav .item.big  → 0,0,3,0  = 30
Trap Specificity never carries across levels — 11 classes (110) still lose to one id (100)? No. Compare column by column: id column 0 vs 1 → the id wins. That is why "just add another class" sometimes doesn't work.

B4. Box model & box-sizing

*{ box-sizing:border-box; }   /* width includes padding + border */

Default is content-box, where width:200px + padding:20px + border:1px renders as 242px. With border-box it stays 200px.

B5. Flexbox — one axis

.row{
  display:flex;
  align-items:center;      /* cross axis */
  justify-content:space-between; /* main axis */
  gap:12px;
}
.push{ margin-left:auto; }  /* shove the rest to the right */
.fixed{ flex:none; }        /* = 0 0 auto, never shrink */

flex:1 is shorthand for flex:1 1 0% — grow, shrink, ignore content size. flex:auto is 1 1 auto — respects content width.

Flex item overflowing? Add min-width:0 — flex items default to min-width:auto.

B6. Grid — two axes

.stage{
  display:grid;
  grid-template-columns: minmax(0,1fr) 44px;
}
.cards{
  grid-template-columns: repeat(auto-fill, minmax(212px,1fr));
}
auto-fillauto-fit
Few itemsKeeps empty tracksCollapses empties, items stretch

Flex vs Grid: flex is content-driven and one-dimensional; grid is layout-driven and two-dimensional. Toolbar → flex. Page skeleton or card grid → grid.

B7. Positioning & stacking context

ValueBehaviour
staticDefault; ignores top/left
relativeOffset from itself; space preserved
absoluteRemoved from flow; positions to nearest positioned ancestor
fixedPositions to viewport
stickyRelative until a scroll threshold, then fixed

position:sticky needs a threshold (top:0) and an ancestor that is not overflow:hidden — the single most common reason sticky "doesn't work".

A stacking context is created by: root, position + z-index, opacity < 1, transform, filter, will-change, backdrop-filter. Inside one, z-index:9999 can still sit behind a sibling context with z-index:1.

B8. Pseudo-elements

.ornament::before{ content:""; flex:1; height:1px; }
p.is-opening::first-letter{ float:left; font-size:3.4em; }
p.is-opening::first-line{ font-variant:small-caps; }
li::marker{ color:var(--clay); }
::selection{ background:var(--accent-surface); }

Both ::before and ::after need content, even if empty. They don't work on replaced elements (img, input).

B9. Pseudo-classes worth knowing

:focus-visibleFocus ring for keyboard users only, not mouse clicks
:focus-withinParent styles when any child has focus
:not(x)Negation; takes the specificity of its argument
:is() / :where()Grouping; :where() has zero specificity
:nth-child(2n+1)Position among all siblings
:nth-of-type()Position among siblings of that tag

B10. Transitions, transforms, animations

.btn{ transition: background 220ms cubic-bezier(.22,.61,.36,1); }

@keyframes float{
  0%,100%{ translate:0 0; }
  50%    { translate:0 -10px; }
}
.sheet{ animation: float 7s ease-in-out infinite; }

Only animate transform and opacity. They are handled by the compositor — no layout, no repaint. Animating width, top or margin forces layout on every frame and drops you below 60fps.

ChangeCost
width, height, top, margin, font-sizeLayout → Paint → Composite (worst)
color, background, box-shadowPaint → Composite
transform, opacityComposite only (best)

B11. clamp(), min(), max(), calc()

font-size: clamp(28px, 3.8vw, 42px);  /* min, preferred, max */
left: max(18px, calc(50% - 560px));
width: min(100%, 820px);

clamp() gives fluid typography with no media queries at all.

B12. Media queries & user preferences

@media (max-width: 900px){ ... }
@media (prefers-color-scheme: dark){ ... }
@media (prefers-reduced-motion: reduce){
  *{ animation-duration:.01ms !important;
     transition-duration:.01ms !important; }
}
@media print{ .no-print{ display:none !important; } }

Mobile-first uses min-width and builds up; desktop-first uses max-width and strips down. Pick one and stay consistent.

Accessibility prefers-reduced-motion is not optional polish — motion can trigger nausea and migraines for people with vestibular disorders. One block covers your whole site.

B13. color-mix() and modern colour

background: color-mix(in srgb, var(--bg) 84%, transparent);
border-color: color-mix(in srgb, var(--ok) 30%, var(--line));

Mixes two colours at runtime — so a translucent header works in any theme without hardcoding rgba values twice.

B14. Logical properties

margin-inline: auto;      /* left + right   */
padding-block: 24px;      /* top + bottom   */
inset-block: 0;           /* top:0; bottom:0 */
border-inline-start: 3px; /* left in LTR, right in RTL */

They follow writing direction, so a right-to-left language (Arabic, Urdu) mirrors correctly with no extra CSS. Relevant here — the app supports Hindi.

B15. Overflow & scroll containers

overflow:auto scrolls only when needed; scroll always shows a bar; hidden clips and breaks any sticky descendant; clip clips without creating a scroll container.

.tabs{ overflow-x:auto; scrollbar-width:none; }
.tabs::-webkit-scrollbar{ display:none; }

B16. BEM naming

.hdr            /* Block   */
.hdr__title     /* Element */
.hdr--compact   /* Modifier*/

Keeps specificity flat (every selector is one class), makes the HTML–CSS relationship obvious, and avoids deep nesting like .header .nav ul li a.

B17. Print stylesheets

@page{ size:A4; margin:13mm; }
@media print{
  .no-print{ display:none !important; }
  pre{ break-inside:avoid; }
  h2 { break-after:avoid; }
}

break-inside:avoid stops a code block splitting across pages — exactly how this PDF was made.

B18. Performance: reflow vs repaint

  • Reflow (layout) — geometry changed; browser recalculates positions. Expensive.
  • Repaint — only pixels changed (colour). Cheaper.
  • Composite — layers moved on the GPU. Cheapest.

Layout thrashing = writing then reading layout in a loop:

// BAD — forces reflow every iteration
items.forEach(el => { el.style.width = el.offsetWidth + 10 + 'px'; });

// GOOD — read all, then write all
const widths = items.map(el => el.offsetWidth);
items.forEach((el,i) => el.style.width = widths[i] + 10 + 'px');

Part C — JavaScript Concepts

C1. IIFE and the module pattern

const Settings = (() => {
  let state = {};                 // private
  function get(k){ return state[k]; }
  function set(k,v){ state[k]=v; }
  return { get, set };            // public surface
})();

An IIFE (Immediately Invoked Function Expression) runs once and creates a scope. Everything inside is private; only what you return is reachable. This is encapsulation via closure — the pattern every library used before ES modules.

C2. Closures

A function remembers the scope it was created in, even after that outer function has finished.

function counter(){
  let n = 0;                // stays alive
  return () => ++n;
}
const next = counter();
next(); next();             // 1, then 2

C3. var / let / const, hoisting, TDZ

ScopeHoistedRedeclare
varfunctionYes → undefinedYes
letblockYes, but in TDZNo
constblockYes, but in TDZNo

TDZ (Temporal Dead Zone) = the gap between entering a block and the declaration line. Touching the variable there throws ReferenceError.

const stops reassignment, not mutation — const a=[]; a.push(1) is legal.

C4. this and arrow functions

const obj = {
  name:'A',
  regular(){ return this.name; },       // 'A'
  arrow: () => this.name                // undefined
};

A normal function's this depends on how it is called. An arrow function has no own this — it borrows from where it was defined. That is why arrows are perfect for callbacks and wrong for object methods.

C5. Event loop, microtasks, macrotasks

console.log('1');
setTimeout(()=>console.log('2'), 0);   // macrotask
Promise.resolve().then(()=>console.log('3')); // microtask
console.log('4');
// 1, 4, 3, 2

Order: run all sync code → drain the entire microtask queue → take one macrotask → repeat. Microtasks (promises, queueMicrotask) always beat setTimeout.

C6. Event bubbling, capturing, delegation

An event goes capture (window → target), hits the target, then bubbles (target → window). Listeners are on the bubble phase unless you pass {capture:true}.

document.addEventListener('click', e => {
  const tab = e.target.closest('.rail__tab');
  if (tab) goToChapter(Number(tab.dataset.chapter));
});

Delegation = one listener on a parent instead of N on children. Cheaper in memory, and it works for elements added later. Requires closest() because e.target may be an inner <svg>.

stopPropagation() halts bubbling. preventDefault() cancels the default action. They are unrelated.

C7. DOM query & manipulation

document.querySelector('.btn')       // first match or null
document.querySelectorAll('.btn')    // static NodeList
document.getElementsByClassName()    // LIVE HTMLCollection

el.classList.add / remove / toggle('is-on')
el.classList.toggle('is-on', force)  // force = boolean
el.setAttribute('aria-expanded','true')

Static vs live: a NodeList from querySelectorAll is a snapshot. An HTMLCollection updates itself — which can cause infinite loops if you append inside a loop over it.

C8. innerHTML vs textContent vs innerText

innerHTMLParses HTML. XSS risk with user input.
textContentRaw text, ignores CSS, fast, safe.
innerTextRendered text — respects display:none, triggers reflow.

Rule: user data always goes through textContent.

C9. Storage

LivesSizeSent to server
localStorageUntil cleared~5–10MBNo
sessionStorageUntil tab closes~5MBNo
CookiesExpiry date~4KBYes, every request
try{
  localStorage.setItem('k', JSON.stringify(obj));
}catch{
  // Safari private mode throws QuotaExceededError
}

Storage is synchronous and strings-only. Always wrap in try/catch and always JSON.parse defensively.

C10. Optional chaining & nullish coalescing

el?.dataset?.action          // undefined instead of throwing
fn?.()                       // call only if it exists

a ?? b   // b only if a is null/undefined
a || b   // b if a is falsy (0, '', false too!)
Classic trap count || 10 returns 10 when count is 0. count ?? 10 correctly returns 0. Use ?? for numbers.

C11. Destructuring, spread, rest, defaults

const [a, b] = [1, 2];
const { title, mins = 10 } = chapter;      // default
const copy = { ...obj, done:true };        // spread (shallow!)
function f(first, ...rest){}               // rest

Spread is a shallow copy — nested objects are still shared references. Deep copy: structuredClone(obj).

C12. Array methods

map     → new array, same length
filter  → new array, fewer items
reduce  → single value
forEach → nothing (side effects only)
find / findIndex / some / every / includes
flat / flatMap / at(-1)

Mutating: push, pop, splice, sort, reverse.
Non-mutating: map, filter, slice, concat, toSorted, toReversed.

sort() mutates AND sorts as strings by default: [10,9].sort() → [10,9]. Pass a comparator.

C13. Template literals

const html = `<button data-n="${n}">${label}</button>`;

Multi-line, interpolation, and expressions inside ${}. Building markup with .map().join('') is fast and readable — but remember C8 about escaping.

C14. Set and Map

const seen = new Set();     seen.add(x); seen.has(x);
const listeners = new Set(); // used for the settings observers
[...new Set(arr)]            // dedupe an array

Map keys can be any type and keep insertion order; object keys are strings only.

C15. matchMedia — media queries in JS

const mq = matchMedia('(prefers-color-scheme: dark)');
mq.matches;                       // boolean, right now
mq.addEventListener('change', fn); // react to OS change

C16. IntersectionObserver

const io = new IntersectionObserver((entries, obs) => {
  entries.forEach(e => {
    if (!e.isIntersecting) return;
    e.target.classList.add('is-in');
    obs.unobserve(e.target);       // fire once
  });
}, { threshold:.12, rootMargin:'0px 0px -12% 0px' });

items.forEach(el => io.observe(el));

Async and off the main thread — far cheaper than a scroll listener calling getBoundingClientRect(). Used for scroll reveal, lazy loading, infinite scroll.

C17. setTimeout, debounce, throttle

// DEBOUNCE — run once, after the user stops
function debounce(fn, wait){
  let t;
  return (...args) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), wait);
  };
}

// THROTTLE — run at most once every `wait`
function throttle(fn, wait){
  let ready = true;
  return (...args) => {
    if (!ready) return;
    ready = false;
    fn(...args);
    setTimeout(() => ready = true, wait);
  };
}

Debounce → search input, resize. Throttle → scroll, mousemove.

C18. getComputedStyle

const css = getComputedStyle(document.documentElement);
css.getPropertyValue('--accent').trim();   // read a CSS variable

Returns the resolved value after the cascade — el.style.x only sees inline styles. Forces a reflow, so don't call it in a loop.

C19. requestAnimationFrame

requestAnimationFrame(() => el.style.strokeDashoffset = target);

Runs before the next paint (~60fps), pauses in background tabs. Use it to let the browser apply an initial style before you change it, so a transition actually animates instead of jumping.

C20. Strings, numbers, coercion

'5' + 3    // '53'  (+ prefers string)
'5' - 3    // 2     (- is numeric only)
[] + {}    // '[object Object]'
0.1 + 0.2  // 0.30000000000000004

String(n).padStart(2,'0')   // '03'
Number('3')  parseInt('3px')  // 3, 3
(2*Math.PI*r).toFixed(1)

== coerces, === does not. Always use === except x == null, which neatly catches both null and undefined.

Part D — Interview Questions: HTML

What is semantic HTML and why use it?Basic
Using tags that describe meaning rather than appearance — header, nav, main, article, aside, footer. Benefits: screen readers build a landmark map so users can jump between regions, search engines understand document structure, and the markup is self-documenting for other developers.
Difference between <section> and <div>?Basic
section is a thematic grouping and should have a heading; it appears in the document outline. div carries no meaning and exists purely for styling or layout. If removing the tag loses no meaning, it should have been a div.
How many <main> elements per page?Basic
One visible main. You may have others only if the rest are hidden. It represents the dominant content, excluding repeated headers, navs and footers.
What does the viewport meta tag do?Basic
It tells mobile browsers to use the real device width instead of a simulated ~980px one. Without it the page renders wide and scales down, and CSS media queries never match, so a responsive layout looks desktop-sized and tiny on a phone.
What are data-* attributes and how do you read them?Basic
Custom attributes for attaching your own data to markup, valid in HTML5. Read via el.dataset.name, where data-user-id becomes dataset.userId. Values are always strings, so numbers need Number(). In our project data-theme on <html> drives all CSS theming.
Difference between hidden, display:none, visibility:hidden and opacity:0?Medium
hidden and display:none remove the element from layout and from the accessibility tree. visibility:hidden keeps the space but hides it from both. opacity:0 keeps space, and the element is still focusable, clickable and read by screen readers — a common accessibility bug. Note hidden is overridden by any display rule.
Explain defer vs async.Medium
Both download in parallel with parsing. async executes the moment it finishes downloading, so execution order between scripts is not guaranteed — fine for independent scripts like analytics. defer waits until HTML parsing completes and runs scripts in document order — correct when scripts depend on each other or on the DOM.
Your site flashes white before dark mode applies. Why, and how do you fix it?Hard
Because the saved theme is applied by a deferred or bottom-of-body script that runs after first paint. The fix is a small blocking inline script in <head> that reads localStorage and sets document.documentElement.dataset.theme before the browser paints. It must be inline and synchronous — an external file reintroduces the flash. Keep it tiny, since it blocks rendering.
When would you use aria-label vs aria-labelledby?Medium
aria-label supplies a string directly, for icon-only controls with no visible text. aria-labelledby points at the id of existing visible text, which is better when the label is already on screen — it stays in sync and gets translated.
What is a skip link and why does it exist?Medium
The first focusable element on the page, visually hidden until focused, linking to #main. It lets keyboard and screen-reader users bypass a long repeated navigation instead of tabbing through it on every page. It's a WCAG requirement (2.4.1 Bypass Blocks).
Why prefer <button> over <div onclick>?Medium
A button is focusable by default, fires on Enter and Space, is announced as a button, supports disabled, and participates in forms. A div needs tabindex="0", role="button" and manual keyboard handlers to match — and people usually forget the Space key.
What does currentColor do in SVG?Medium
It resolves to the inherited CSS color of the element. Setting stroke="currentColor" means one icon automatically matches its parent's text colour in light mode, dark mode and on hover, with no extra rules and no duplicate icon files.
What is viewBox and how does it differ from width/height?Hard
viewBox="0 0 24 24" defines the internal coordinate system — the user-space window onto the drawing. width/height define the rendered size on the page. Because the two are independent, the same path data scales to 14px or 64px with no distortion. Without a viewBox, the SVG cannot scale responsively.
How do you make a custom accordion accessible?Hard
The trigger is a <button> carrying aria-expanded="true|false", toggled in JS, and aria-controls pointing at the panel id. The panel uses the hidden attribute so it leaves the a11y tree when closed. Update the visible label text too. Or use native <details>/<summary> and write no JS at all.

Part E — Interview Questions: CSS

Explain the box model.Basic
Content, then padding, then border, then margin. With the default content-box, width applies to content only, so padding and border add on top. box-sizing:border-box makes width include padding and border, which is why almost every project sets it globally.
How is specificity calculated?Basic
Four columns: inline styles, ids, classes/attributes/pseudo-classes, then elements/pseudo-elements. Compare left to right; a higher column always wins regardless of counts in lower ones — so one id beats any number of classes. Ties go to the later rule in source order.
CSS variables vs Sass variables?Basic
Sass variables are compiled away at build time — static. CSS custom properties are live in the browser: they inherit, cascade, can be changed by media queries or JavaScript, and can be overridden on a subtree. That is what makes runtime theming possible.
When do you choose Flexbox over Grid?Basic
Flexbox for one dimension and content-driven sizing — toolbars, button rows, a header. Grid for two dimensions and layout-driven sizing — page skeletons, card grids, anything where you want to define the structure up front. They compose happily: grid for the page, flex inside cells.
Why is my position:sticky not working?Medium
Three usual causes: no threshold set (needs top, bottom, left or right); an ancestor has overflow:hidden/auto/scroll, which makes it the scroll container; or the parent isn't tall enough to scroll within. Sticky is relative to the nearest scrolling ancestor, not the viewport.
What creates a stacking context?Hard
The root element, plus any element with: position other than static and a z-index other than auto; opacity below 1; a transform, filter, perspective, backdrop-filter, will-change, contain:paint, or isolation:isolate. Inside a context, children can never escape it — which is why a z-index:9999 modal can still sit behind a header whose parent has transform applied.
Difference between :focus and :focus-visible?Medium
:focus matches any focus, including a mouse click — which is why people used to remove outlines and break keyboard access. :focus-visible matches only when the browser thinks a focus ring is useful, essentially keyboard navigation. Style :focus-visible and everyone gets the right behaviour.
Which CSS properties are cheap to animate, and why?Hard
transform and opacity. They can be handled entirely by the compositor on the GPU, skipping layout and paint. Animating width, height, top or margin triggers layout on every frame for that element and often its siblings, which is what drops you below 60fps.
Explain clamp().Medium
clamp(min, preferred, max). The preferred value is usually fluid (vw or a calc), and the browser keeps the result between the bounds. It gives responsive type with no media queries — clamp(28px, 3.8vw, 42px) scales smoothly but never gets unreadably small or comically large.
What's the difference between auto-fill and auto-fit?Hard
With few items, auto-fill creates empty tracks that reserve space, so your items stay their minimum width and leave a gap. auto-fit collapses the empty tracks to zero so the existing items stretch to fill the row. Identical when the row is full.
How does gap differ from margin?Basic
gap spaces between children only — no leading or trailing space, and no need for :last-child resets or negative margins on the container. It works in flex, grid and multi-column.
A flex item with long text overflows its container. Why?Hard
Flex items default to min-width:auto, which means "never shrink below my content's intrinsic size". The fix is min-width:0 on the item (or overflow:hidden), which allows it to shrink so text-overflow:ellipsis can work. Same applies to grid items with minmax(0,1fr).
What is color-mix() useful for?Medium
Blending two colours at runtime — color-mix(in srgb, var(--bg) 84%, transparent). For a translucent sticky header it means one rule works in both light and dark themes, instead of hardcoding two different rgba values.
Mobile-first vs desktop-first — which and why?Medium
Mobile-first writes base styles for small screens and adds complexity with min-width. It tends to produce less CSS, forces content priority decisions early, and matches how most traffic actually arrives. Desktop-first with max-width is valid for content-heavy dashboards. The real rule is to pick one and never mix directions.
What does prefers-reduced-motion do?Medium
It matches when the user has asked their OS to minimise animation. Motion can cause nausea and migraines for people with vestibular disorders, so respecting it is an accessibility requirement, not a nicety. One global block that reduces all durations to near-zero covers a whole site.
Reflow vs repaint vs composite?Hard
Reflow (layout) recalculates geometry and can cascade to other elements — the most expensive. Repaint redraws pixels without changing geometry, e.g. a colour change. Composite just moves existing layers on the GPU — the cheapest, and where transform/opacity land.
What is layout thrashing?Hard
Interleaving reads of layout properties (offsetWidth, getBoundingClientRect, getComputedStyle) with writes inside a loop. Each read forces the browser to flush pending style changes and recalculate layout synchronously. Fix by batching — read everything first, then write everything.
Explain BEM and what problem it solves.Basic
Block, Element, Modifier — .card, .card__title, .card--featured. Every selector is a single class, so specificity stays flat and predictable, names are self-documenting, and you avoid brittle descendant chains like .sidebar .list li a that break when markup moves.
How would you implement dark mode?Hard
Define semantic custom properties on :root, override them under [data-theme="dark"], and have every component consume only those variables. Default to the OS via prefers-color-scheme, let the user override, persist the choice in localStorage, and apply it with a blocking inline script in <head> to avoid a flash. JavaScript then only ever changes one attribute.
Difference between :nth-child and :nth-of-type?Medium
:nth-child(2) matches an element that is the second child of its parent and matches the selector — so p:nth-child(2) fails if the second child is a div. p:nth-of-type(2) counts only p siblings, so it matches the second paragraph regardless of what else is interleaved.
What is the difference between :is() and :where()?Hard
Both group selectors to shorten lists. :is() takes the specificity of its most specific argument; :where() always has zero specificity. Use :where() for resets and defaults so authors can override them with a single class.
When do margins collapse?Hard
Adjacent vertical margins between block siblings collapse to the larger of the two; a parent's top margin collapses with its first child's; and an empty block's own top and bottom collapse. It does not happen with flex or grid children, floats, absolutely positioned elements, or when padding, border or overflow separates them.
How do logical properties help?Medium
margin-inline, padding-block, border-inline-start and inset-block follow the writing direction rather than physical screen edges. In a right-to-left language the layout mirrors automatically, with no duplicate RTL stylesheet.
You need a translucent blurred header. What's the catch?Hard
backdrop-filter gives the blur, but it creates a stacking context, so z-index inside behaves relative to it. It's also GPU-expensive on long scrolling pages, needs the -webkit- prefix for older Safari, and requires a semi-transparent background — with a fully opaque one there is nothing to blur.

Part F — Interview Questions: JavaScript

Explain var, let and const.Basic
var is function-scoped and hoisted as undefined. let and const are block-scoped and hoisted into the Temporal Dead Zone, so accessing them before declaration throws a ReferenceError. const prevents reassignment, not mutation — you can still push to a const array.
What is a closure? Give a real use.Basic
A function that keeps access to the scope it was created in, even after the outer function returns. Real uses: private state in the module pattern, the t variable inside a debounce, and memoisation caches. In our settings module, state is a closure variable no outside code can reach.
Difference between == and ===?Basic
=== compares type and value with no coercion. == coerces first, giving surprises like '' == 0 and null == undefined being true. Use === everywhere, with the one idiomatic exception of x == null to test for null or undefined together.
What is event bubbling?Basic
After an event fires on its target it travels up through every ancestor to the document, firing the same-named listeners. The opposite phase, capturing, runs top-down first and you opt into it with {capture:true}. Bubbling is what makes delegation possible.
Explain event delegation and when it's the right choice.Medium
Attach one listener to a common ancestor and identify the real source with e.target.closest('.selector'). It's better when you have many similar children, when children are added or removed dynamically, or when you'd otherwise attach and detach listeners repeatedly. closest() matters because the click may land on a nested icon rather than the button.
stopPropagation() vs preventDefault()?Medium
Unrelated. preventDefault() cancels the browser's default action — form submit, link navigation. stopPropagation() stops the event travelling further up the tree, which will silently break any delegated listener above you. return false in a jQuery handler did both; in plain JS it does neither.
Predict the output: sync, setTimeout, promise.Medium
Sync code first, then the entire microtask queue (promise callbacks), then one macrotask (setTimeout). So log(1); setTimeout(log(2),0); Promise.resolve().then(log(3)); log(4) prints 1, 4, 3, 2. A setTimeout(fn, 0) is never truly zero — minimum ~4ms and it waits for the current task plus all microtasks.
Arrow functions vs regular functions?Medium
Arrows have no own this, arguments, super or prototype, and cannot be used with new. Their this is lexical — taken from where they were defined. That makes them ideal as callbacks and wrong as object methods or constructors.
What does this refer to?Hard
It depends on the call site. Plain call → undefined in strict mode, global otherwise. Method call → the object before the dot. new → the new instance. call/apply/bind → whatever you pass. Arrow → inherited from the enclosing scope. DOM handler → the element the listener is attached to.
Difference between innerHTML and textContent?Basic
innerHTML parses the string as HTML, so injecting user input is an XSS vulnerability. textContent sets raw text and is both safer and faster. A third, innerText, returns rendered text — it respects display:none and triggers a reflow to compute.
localStorage vs sessionStorage vs cookies?Basic
localStorage persists until cleared, ~5–10MB, never sent to the server. sessionStorage is identical but dies with the tab. Cookies are ~4KB and are attached to every HTTP request, which makes them right for auth tokens and wrong for app state. All are origin-scoped; the two storages are synchronous and strings-only.
Why wrap localStorage in try/catch?Medium
It throws in several real situations: Safari private browsing, a full quota, disabled storage in browser settings, or a sandboxed iframe. It also throws on JSON.parse if the stored value is corrupt. Since it's non-critical, catching and falling back to defaults keeps the app alive.
Debounce vs throttle — write one.Hard
Debounce delays until activity stops (search-as-you-type, resize end). Throttle guarantees at most one call per interval (scroll, mousemove). 
const debounce=(fn,ms)=>{let t;return(...a)=>{clearTimeout(t);
  t=setTimeout(()=>fn(...a),ms);};};
What is IntersectionObserver and why is it better than scroll listeners?Medium
It asynchronously notifies you when an element enters or leaves a viewport or root, without running code on every scroll frame. A scroll handler calling getBoundingClientRect() forces synchronous layout repeatedly. IO runs off the main thread, supports thresholds and rootMargin, and you can unobserve once fired.
Explain the module pattern with an IIFE.Medium
An immediately-invoked function creates a private scope; you return only the public API. Everything else — state, helpers — is unreachable from outside, achieved purely through closure. It was the standard way to avoid globals before ES modules, and it's still useful in a no-build project like this one.
?? vs ||?Medium
|| falls back on any falsy value, including 0, '' and false. ?? falls back only on null or undefined. So count || 10 wrongly gives 10 when count is 0, whereas count ?? 10 correctly gives 0.
Shallow vs deep copy?Medium
Spread and Object.assign copy one level — nested objects remain shared references, so mutating them affects both copies. For a deep copy use structuredClone(obj), which also handles Dates, Maps and Sets; JSON.parse(JSON.stringify(x)) works but loses functions, undefined and Dates.
Which array methods mutate?Basic
Mutating: push, pop, shift, unshift, splice, sort, reverse, fill. Non-mutating: map, filter, slice, concat, flat and the newer toSorted, toReversed, toSpliced, with. Note sort() both mutates and compares as strings by default, so [10,9,1].sort() gives [1,10,9].
NodeList vs HTMLCollection?Hard
querySelectorAll returns a static NodeList — a snapshot with forEach. getElementsByClassName/TagName return a live HTMLCollection that updates as the DOM changes and has no array methods. Looping over a live collection while appending matching elements creates an infinite loop.
What is getComputedStyle and its cost?Hard
It returns the final resolved value of every property after the cascade, unlike el.style which only sees inline styles. It's the way to read a CSS custom property from JS. Because it must flush pending style and layout work, calling it inside a loop causes layout thrashing.
Why requestAnimationFrame before changing a property you want to transition?Hard
If you add an element and set its final value in the same frame, the browser never recorded a starting value, so it jumps instead of animating. Deferring the change to the next frame guarantees the initial style is committed first, so the transition has two states to interpolate between.
How do you read a CSS variable from JavaScript, and set one?Medium
Read with getComputedStyle(document.documentElement).getPropertyValue('--accent').trim() — the trim matters because the value keeps its leading whitespace. Set with el.style.setProperty('--accent', '#fff'). Setting it on an element scopes the change to that subtree.
Explain hoisting precisely.Medium
During the creation phase the engine registers declarations before executing code. Function declarations are fully hoisted and callable early. var is hoisted and initialised to undefined. let/const/class are hoisted but uninitialised — the TDZ — so early access throws. Function expressions follow their variable's rules.
What's wrong with for (var i...) inside a loop of callbacks?Hard
var is function-scoped, so all callbacks close over the same i and see its final value. let creates a fresh binding per iteration and fixes it. Pre-ES6 the workaround was an IIFE capturing i as a parameter.
How would you persist and restore UI state across reloads?Medium
Keep one namespaced key holding a JSON object rather than many keys. Validate on read against a schema of allowed values so a corrupt or stale entry falls back to defaults, wrap both read and write in try/catch, and apply the state as early as possible — for anything visual, in a blocking head script to avoid a flash.
What is the observer pattern and where did you use it?Hard
A subject keeps a list of callbacks and notifies them on change. In the settings module, onChange(fn) adds to a Set and returns an unsubscribe function; set() notifies everyone. The header, the design panel and the specimen page all react independently, so none of them needs to know the others exist.
Why a Set for listeners rather than an array?Hard
A Set silently prevents the same callback being registered twice, and delete is O(1) by reference rather than indexOf plus splice. It also can't be corrupted by index manipulation elsewhere.
How do you avoid XSS when building HTML from data?Hard
Prefer textContent or createElement with property assignment. If you must build a string, escape & < > " ' before interpolation, never let user data land inside an attribute without quoting, and never build <script>, href="javascript:" or event-handler attributes from input. Consider a Content-Security-Policy and, on modern browsers, Trusted Types.
What does e.target vs e.currentTarget mean?Medium
target is the deepest element where the event originated — possibly a nested span or svg. currentTarget is the element whose listener is currently running. In delegation you read target and walk up with closest(); currentTarget is only valid during dispatch.
How would you make an icon system without an icon font?Medium
Store path data in a JS object keyed by name, and render inline SVG with fill="none" stroke="currentColor" and a shared viewBox. Icons then inherit colour and size from CSS, need no extra network request, and can't produce the flash-of-invisible-icon that fonts do. A helper replaces every [data-ico] placeholder on load.
Explain matchMedia and following the OS theme.Medium
matchMedia('(prefers-color-scheme: dark)') gives a MediaQueryList with a matches boolean and a change event. The trick is to only follow the OS while the user hasn't chosen explicitly — store null as "no preference" and re-read the query on change, so the site flips at sunset for users who never touched the toggle.
Your click handler stopped working for new elements. Why?Hard
Listeners bind to element references, not selectors, so anything created after querySelectorAll ran has none. Either re-bind after every render — cheap to forget and leaks if you don't remove the old ones — or delegate from a stable ancestor. A second cause is an inner handler calling stopPropagation() and killing the delegated listener.

Code-writing questions

Write a theme toggle that persists and follows the OS by default.
const KEY = 'theme';

function current(){
  const saved = localStorage.getItem(KEY);
  if (saved === 'light' || saved === 'dark') return saved;
  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}
function apply(t){ document.documentElement.dataset.theme = t; }
function toggle(){
  const next = current() === 'dark' ? 'light' : 'dark';
  localStorage.setItem(KEY, next);
  apply(next);
}
apply(current());
matchMedia('(prefers-color-scheme: dark)')
  .addEventListener('change', () => { if (!localStorage.getItem(KEY)) apply(current()); });
Mention the head script for FOUC and that CSS does all the styling off [data-theme].
Implement event delegation for a list of buttons.
list.addEventListener('click', e => {
  const btn = e.target.closest('[data-id]');
  if (!btn || !list.contains(btn)) return;
  select(Number(btn.dataset.id));
});
The contains check guards against closest() escaping the container when markup is nested unexpectedly.
Write debounce, then explain where you'd use throttle instead.
function debounce(fn, wait = 300){
  let t;
  return function (...args){
    clearTimeout(t);
    t = setTimeout(() => fn.apply(this, args), wait);
  };
}
Use function not an arrow so this passes through. Debounce for search input and resize; throttle for scroll and mousemove where you need periodic updates.
Build a scroll-reveal that fires once per element.
const io = new IntersectionObserver((entries, obs) => {
  for (const e of entries){
    if (!e.isIntersecting) continue;
    e.target.classList.add('is-in');
    obs.unobserve(e.target);
  }
}, { threshold: 0.12 });

document.querySelectorAll('.reveal').forEach(el => io.observe(el));
Add a prefers-reduced-motion guard that just adds the class to everything.
Write an accessible accordion toggle.
btn.addEventListener('click', () => {

  btn.setAttribute('aria-expanded', String(!open));
  panel.hidden = open;

Key points: the trigger is a real <button>, state lives in aria-expanded, and hidden removes the panel from the a11y tree.
Draw a progress ring with SVG and set it from JS.

circle.setAttribute('stroke-dasharray', C);

Make a tiny pub/sub store with subscribe and unsubscribe.
function createStore(initial = {}){
  let state = { ...initial };
  const subs = new Set();
  return {
    get: k => state[k],
    set(k, v){
      if (state[k] === v) return;      // skip no-op updates
      state = { ...state, [k]: v };
      subs.forEach(fn => fn(k, v));
    },
    subscribe(fn){ subs.add(fn); return () => subs.delete(fn); }
  };
}
Returning the unsubscribe function from subscribe is the detail interviewers look for — it prevents leaks.

Part H — Last-Minute Revision Sheet

Say these out loud before you walk in

  • Specificity — inline 1000, id 100, class 10, element 1. Compare column by column.
  • Sticky fails because of a missing threshold or an overflow:hidden ancestor.
  • Animate only transform and opacity. Everything else costs layout.
  • Event loop — sync → all microtasks → one macrotask → repeat.
  • Closure — a function plus the scope it was born in.
  • Arrow functions have no own this.
  • Delegation — one listener + closest(); works for future elements.
  • innerHTML is an XSS hole; textContent is not.
  • Spread is shallow. structuredClone is deep.
  • 0 || 10 is 10; 0 ?? 10 is 0.
  • flex item overflowing? min-width:0.
  • Dark mode — semantic CSS variables + one attribute + head script for FOUC.

The third beat is what they're actually listening for.
